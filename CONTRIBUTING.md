# Contributing and review protocol

This is a course prototype, not a production grant-review service. Contributions should use synthetic, public, or explicitly authorized data only. Do not commit credentials, private grant documents, or real applicant data.

1. Explain the requirement or defect addressed and any affected human-authority boundary.
2. Keep changes scoped and reviewable; preserve source provenance and immutable history.
3. Add or update relevant automated tests, including failure cases.
4. Run `python -m pytest -q` before proposing changes.
5. Document material AI assistance, human validation, limitations, and any rejected generated output.
6. Have the project owner review changes before committing or publishing.

No external contributions or pull requests are implied to have occurred.
